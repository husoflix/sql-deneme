	1-status code 
http durum komutları (status code) sunucunun isteğe verdiği kısa cevaplardır

1xx >> bilgilendirme 
2xx >> başarılı (istemci isteği başarıyla işlendi) örnekler :
	200 OK > get isteği başarılı , body içinden veri alır 
	201 created > yeni kaynak oluşturuldu (post sonrası)
	204 no contect> başarılı ama body yok (ör: delete)
3xx >> yönlendirme (başka bir url ye yönlendirme ) (redirect) ör: 301 moved permanently , 302 found 

4xx >> istemci hataları 
	400 bad request > geçersiz istek 
	401 unauthorized > kimlik doğrulama başarasız
	403 forbidden > yetki yok 
	404 not found > kaynak yok 
	409 conflict > çakışma 
5xx >> sunucu hataları 
	500 internal server error > sunucuda bişeyler patladı ama fazla detay veremem 
	501 not implemented > sunucu bu methodu desteklemiyor (api dökümanını düzelt)
	502 bad gateway > sunucu arka taraftan bi dönüt alamıyorsa döner 
	503 service unavailable > sunucu geçici olarak hizmet veremiyor(bakım trafik aşırı yüklenmiş
	
	2-put/push/post vs (http metodları farkı)
get >> veri alır safe (değiştirmez) idempotent(aynı isteği tekrar etmek aynı sonucu verir

post >> yeni kaynak oluşturmak için kullanılır non-idempotent(aynı isteği iki kere gönderirsen iki kaynak oluşabilir)

put >> kaynağı tamamen replace eder idempotent aynı put u tekrar gönderirsen sonuç aynı kalır

patch >> kısmi güncelleme (sadece değişen alanlar) genelde idempotent

delete >> kaynağı siler genelde idempotent

push >> http/2 de server push diye farklı bir konu var (sunucunun client a kaynak psuh etmesi) genelde api tasarımında post put patch kullanılır 

#yeni kullanıcı 

	post/api/users   -> 201 created 

#bir kullanıcıyı tamamen güncelle 

	put/api/users/42 -> 200 ok

#sil
	delete/api/users/42 ->204 no content

	5-network payload
payload :isteğin veya cevabın gövdesi (body) içeriği:

json(application/json) >  en yaygın 
form-urlencoded > html formları için 
multipart/dorm-data dosya upload (form+dosya)
binary > resim video vb

diğer önemli noktalar:
content-type header doğru ayarlanmalı 
contect-length veya chunked transfer-encoding ile gönderilir 
compression(gzip, brotli) ile ağdan geöçen payload küçültülebilir
güvnelik: kullanıcıdan gelen payloadu her zaman validate et ex(json schema input sanitization)


js fetch ile json gönderme:
	örneğin:
fetch('/api/login',{
  method: 'POST',
  headers: {'content-type': 'application/json'},
  body: json.stringify({email:'x@x.com', password'****'})
});

http veriyi düz metin(plain) gönderir -güvenli değil (mitm riski yüksek)

sağladıkları
